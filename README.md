# neuro乐健 · 报名与活动提醒

AstrBot 插件版本 **v0.9.0**，与开源时 AstrBot 显示的版本一致。配套 APK 基于乐健体育 **3.10.3**，两者的版本号含义不同。

本仓库包含 AstrBot 推送插件、独立提醒服务、网站绑定与下载接口、APK 补丁及构建源码。网站先验证用户绑定的 QQ，再为该账号生成专属 APK，首次联网激活后无需再次输入 QQ 或绑定码。

这是基于既有 uni-app 客户端的补丁工程，**不是乐健官方 Android 工程的完整源码**。官方 APK、反编译后的完整业务资源、第三方工具二进制、个人安装包、签名私钥、数据库和任何原部署凭据均不包含在仓库中。部署者需自行取得可使用的官方 3.10.3 APK、Android apksig JAR 并生成自己的签名。

## 功能

- 「去报名」收到明确成功响应后，同步活动、时间、地点；QQ 立即排队发送预约确认，正常情况下约一个轮询周期（默认 20 秒）送达。
- 活动开始前 **30 分钟**再次提醒；「取消报名」成功后取消尚未发送的相关提醒。
- 对尚未开放报名的活动，列表和详情页显示「提醒报名」。设置成功后变为「取消提醒」，并立即排队发送设置确认。
- 报名开放前 **2 分钟**提醒；同一网站账号最多保留 **4 个尚未开放的报名提醒**，不同设备共享限额。
- 提醒状态向服务端同步；倒计时与按钮分行排布，避免「距报名」被挤成竖排。
- 专属版显示名称为「neuro乐健」，包名 `com.neurobot.app`，可与官方 `com.ledreamer.zz` 共存。
- 只提供提醒，不自动报名、不抢名额、不自动取消。官方报名结果始终以学校系统为准。

提醒依赖专属客户端成功同步、网站授权有效、服务与 QQ 在线。只在官方客户端操作的报名或取消不会自动同步到本服务。网络故障可能延迟推送，已发送的 QQ 消息不能撤回。

## 组成与实现

```text
已登录且验证 QQ 的网站用户
  → 网站 /tools/lejian/ → 服务 /issue → 构建含一次性激活授权的 APK
  → APK /activate → 设备专用凭据
  → APK 成功报名/取消或设置报名提醒 → /hook → SQLite 提醒队列
  → AstrBot /pending → /claim-check → QQ 私聊 → /ack
                   ↘ 网站 /comments/bridge/lejian/resolve 复核绑定
```

| 路径 | 内容 |
| --- | --- |
| 根目录 `main.py`、`metadata.yaml`、`_conf_schema.json` | AstrBot 插件，仓库可直接安装 |
| `server/service.py` | Python 标准库 HTTP 服务、账号校验、激活、限额与队列 |
| `server/apk_builder.py` | 为每次下载注入独立授权并构建签名 APK |
| `patch/hook.js` | 保留原请求行为，只在明确成功后同步白名单活动字段 |
| `patch/PersonalizedSigner.java` | 校验证书一致性，签名并验证 v1/v2 |
| `scripts/` | 重打包、共存身份、签名适配、界面补丁、构建与测试工具 |
| `website/` | FastAPI 路由适配器和下载页；接入已有网站身份系统 |
| `docs/DEPLOYMENT.md` | 从签名准备到服务与插件配置的步骤 |
| `docs/WEBSITE.md` | 网站身份接口、数据库契约、权限与令牌说明 |

服务用活动 ID、事件 ID 和事件时间去重，避免重复回调或迟到的报名覆盖较新的取消。领取任务有 10 分钟租约，发送前再确认取消状态和网站绑定，成功后回执；失败最多领取 4 次。机器人运行期间缓存已成功发送的任务 ID，降低回执丢失造成的重复。跨重启和发送超时仍可能重复，不能保证严格“恰好一次”。

APK 补丁严格校验两种 ARM 架构原生库摘要与预期指令，保留登录协议和加密流程，只调整与重新签名、共存包名相关的校验常量；签名常量由部署者的 DER 证书计算。Manifest 与 uni-app UI 补丁也检查预期结构，原版升级后会拒绝构建，需要重新适配，不能仅改版本号。

## 安装流程

完整部署需要 **网站 + 提醒服务 + APK 构建环境 + AstrBot**，仅安装插件不能生成 APK 或完成 QQ 绑定。

1. 克隆仓库，按 [部署文档](docs/DEPLOYMENT.md) 准备 Python 3.12、JDK 17+、官方 APK、apksig 及自己的签名。
2. 按 [网站接入文档](docs/WEBSITE.md) 接入真实登录与已验证 QQ 绑定。网站必须从服务端会话取身份，不接受浏览器指定接收 QQ。
3. 设置独立机器人令牌、网站令牌及绑定复核 URL，启动提醒服务和 HTTPS 反向代理。
4. 在 AstrBot 插件管理中从以下仓库安装：

   `https://github.com/Sonnety14/qqbot-plugin-neuro_leijan.git`

5. 配置以下字段，最后打开 `enabled`。

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `false` | 配置完成后启用轮询 |
| `service_url` | 空 | 提醒服务的内网 origin，例如 `http://127.0.0.1:18090`，不带 `/lejian` 路径 |
| `token` | 空 | 机器人专用令牌；优先读取环境变量 `LEJIAN_BOT_TOKEN` |
| `platform_id` | 空 | 实际 QQ / OneBot 平台实例 ID，不能照抄别人的名称 |
| `interval` | `20` | 轮询秒数，最低 5 秒 |
| `download_url` | 空 | 自己网站的 `https://YOUR_DOMAIN/tools/lejian/` |

AstrBot 平台需支持 `send_private_msg`，用户需要能接收机器人的私聊。容器内 `127.0.0.1` 指向该容器，跨容器请填实际可达的私网服务地址。无需修改插件源码。

## 用户使用

1. 在部署者的网站登录，完成 QQ 归属验证并绑定，打开乐健下载页。
2. 点击「生成并下载我的安装包」。链接只允许该登录用户使用，1 小时有效；安装包在下载后 **7 天内首次联网激活**。
3. 安装「neuro乐健」，登录自己的乐健账号。无需卸载官方版，但后续更新必须沿用同一签名。
4. 报名成功后检查 QQ 预约确认，等待活动前提醒。取消报名以乐健显示成功为准。
5. 对未开始报名的活动点「提醒报名」，收到 QQ 确认后按钮变为「取消提醒」。达到 4 个时先取消一个，才能增加新的提醒。

QQ 命令「乐健绑定」「乐健下载」都会返回管理员配置的下载页。旧的 `LI-...` 绑定码流程已停用。

**☆ 安装包绑定了您的 QQ 号，不要直接分享转发！** APK 不包含 QQ 明文，但包含可激活该账户的授权，不能当成普通公共安装包发布。更换设备、卸载重装或账号授权变更后重新生成。已激活授权仅供该设备使用。

## 隐私与边界

- 提醒上报只包含活动 ID、标题、时间、地点、事件及随机设备标识；不会把乐健密码、Cookie、Authorization、组织 ID、学号或姓名发送给提醒服务器。
- 网站保存账号与验证过的 QQ 对应关系；服务保存账号 ID、QQ、活动和提醒状态。激活码、设备凭据以摘要存储，但 SQLite 中 QQ 和活动内容是明文，必须限制访问并制定保留策略。
- 网站令牌与机器人令牌分开生成，均留在服务端。不要把主站登录密钥、机器人令牌、签名口令放入 APK、前端脚本或 Git。
- 已生成的 APK 文件里有一次性激活授权。服务自动清理过期下载及过期授权，事件/设备历史不会全部自动删除；数据库、备份和构建目录也需要保护。
- 网页必须使用 HTTPS；跨主机传送凭据应使用 TLS 或可信私网。为公网激活接口增加反向代理限流，避免资源耗尽。
- 官方 APK 与第三方库的权利归原作者；本项目 MIT 许可证仅适用于本仓库提供的补丁与服务代码，不替第三方作品授予再分发许可。

## 测试

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
python scripts/test_service.py
python -m pytest tests -q
node scripts/test_hook.js
python scripts/test_app_identity.py
python scripts/test_signing_compat.py
```

无官方 APK 时，真实资源检查会明确跳过；模拟服务和网站测试仍可运行。准备好私有 `build/` 后执行 `python scripts/test_build.py`，检查真实 UI、重打包和签名，输出的 `build/test-only.apk` 含无效测试授权，不用于真实账号。

`scripts/test_plugin.py` 需在已安装 AstrBot 的 Python 环境运行，例如在 AstrBot 容器中设置 `PYTHONPATH=/AstrBot` 后执行；测试使用假的 QQ 客户端，不发送消息。测试输入及产物不会进入 Git。

本次公开版已验证实际 APK 构建与签名、服务逻辑及界面方法；独立部署后仍需自行在手机上核验登录、安装共存和真实推送。

## 常见问题

- **下载页 503**：检查网站令牌、提醒服务、绑定回调和 Java 构建环境。不要公开错误日志中的请求体或凭据。
- **报名成功但没有 QQ 确认**：确认操作来自专属版、首次激活成功、网站 QQ 绑定仍有效；再检查机器人平台与服务连通性。
- **登录异常 / 安装包解析失败**：确认基底仍是支持的 3.10.3，构建证书与签名私钥一致；不要跳过补丁结构检查。不要用任意新版本覆盖原版。
- **更新安装失败**：不同部署者的签名不相同，不能互相覆盖；自己的升级必须保留签名私钥。不要为解决签名问题泄露现有密钥。
- **取消后仍收到消息**：已发出消息不会撤回；检查取消是否成功且已同步。官方客户端中的取消不经过本补丁。
